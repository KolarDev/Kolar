# Portfolio Project Instructions

Read `PRD.md` before making implementation decisions.

`PRD.md` is the source of truth for the product, content direction, visual identity and UX principles.

## Development principles

* Keep the implementation clean and maintainable.
* Prefer simple solutions over unnecessary abstractions.
* Do not introduce dependencies without a reason.
* Preserve the visual direction defined in `PRD.md`.
* Do not turn the website into a developer dashboard, terminal, cyberpunk interface, game, or SaaS landing page.
* Do not use `//` or slash-based developer syntax as a visual design motif.
* Keep navigation conventional and obvious.
* Prioritize accessibility, responsive design and performance.
* Support reduced-motion preferences.
* Do not sacrifice usability for visual experimentation.

## Design priorities

The visual identity should combine:

* Adventurous art direction
* Strong editorial typography
* Natural black / ash / warm off-white / burnt-orange palette
* Expressive composition
* Subtle, intentional motion
* Simple navigation
* Strong engineering storytelling

The hero statement is:

> I build software that works when it matters.

The header should primarily identify:

> Muhyideen Abdulbasit

Do not repeat the name unnecessarily in the hero.

Use one distinctive primary typeface consistently across the website.

## Working style

Before implementing a major feature:

1. Read the relevant section of `PRD.md`.
2. Understand the existing architecture.
3. Prefer modifying existing patterns over creating competing ones.
4. Keep components reusable where that genuinely improves the codebase.
5. Test the result before considering the work complete.

Do not build the entire portfolio as one giant component.
