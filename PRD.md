# Muhyideen Abdulbasit — Personal Portfolio

## 1. Product Definition

A distinctive personal portfolio for **Muhyideen Abdulbasit, Software Engineer**.

This is not a conventional developer portfolio, résumé website, SaaS landing page, or developer dashboard.

The portfolio should feel like an **adventurous digital world with serious engineering underneath it**.

The visual experience should make someone think:

> **“This feels different.”**

while immediately making it clear:

> **“This person builds software.”**

The portfolio serves three audiences:

* Recruiters looking for engineering experience and capability
* Founders/clients looking for someone who can turn ideas into working products
* Engineers interested in how Muhyideen thinks about software and systems

---

# 2. Core Message

The primary hero statement is:

> **I build software that works when it matters.**

Supporting messaging should communicate that Muhyideen works across:

* Backend systems
* Full-stack products
* Infrastructure
* Data systems
* AI-powered software

The positioning should emphasize **building reliable software and bringing ideas to life**, rather than listing technologies.

# 3. Visual Direction

### Overall feeling

The site should be:

* Adventurous
* Expressive
* Artistic
* Curious
* Warm
* Sophisticated
* Slightly mysterious
* Playful
* Technical in subtle ways

Create an original visual identity for Muhyideen.

---

# 4. What To Avoid

Do not turn the portfolio into:

* Cyberpunk
* Hacker UI
* Terminal UI
* Developer dashboard
* Video game
* Futuristic control panel
* SaaS landing page
* Excessive glassmorphism
* Neon-heavy design
* Rainbow gradients
* Giant technology-logo walls
* Fake terminal windows
* A maze or interactive game
* WASD/game-like navigation
* Excessive scroll gimmicks

Most importantly:

### Do NOT use `//` as a visual motif.

Avoid slash-based decorative language such as:

`//`

`SYS://`

`NODE_03`

`AB / 001`

or similar artificial developer labels.

The technical character of the website should come from **content, typography, visual systems, motion and composition**, not fake code syntax.

---

# 5. Colour System

Use a restrained natural palette.

### Primary colours

* Ash black
* Warm off-white
* Burnt orange

Burnt orange is the primary accent.

Use it naturally for:

* Links
* Hover states
* Important interactions
* Highlights
* Illustrations
* Selected states
* Small visual details

The orange should feel **earthy and confident**, not fluorescent or cyberpunk.

The system must work in both:

* Light mode
* Dark mode

Avoid introducing unnecessary colours.

---

# 6. Typography

Typography is part of the site's identity.

Use **one distinctive primary typeface consistently across the website**.

The font should feel:

* Modern
* Artistic
* Sophisticated
* Slightly experimental
* Highly readable
* Confident

It should work for both large expressive headings and normal body text.

Avoid:

* Generic SaaS typography
* Obvious futuristic fonts
* Cyberpunk fonts
* Terminal/monospace aesthetics
* Multiple unrelated font families

Hierarchy should primarily come from:

* Size
* Weight
* Spacing
* Layout
* Composition

Monospace may be used extremely selectively if genuinely useful, but the website must not feel like a terminal.

---

**Muhyideen Abdulbasit**

# 14. Motion & Interaction

Motion is important but must remain intentional.

Use:

* Elegant page transitions
* Scroll-based composition changes
* Image transitions
* Object movement
* Hover interactions
* Visual reveals
* Subtle depth/parallax where appropriate

Do not animate everything.

Motion should make the site feel alive, not distracting.

Always consider:

* Performance
* Mobile devices
* Accessibility
* Reduced-motion preferences

The user should never have to perform a special interaction to understand or navigate the site.

---

# 15. Responsive Design

The design must work naturally across:

* Desktop
* Tablet
* Mobile

Do not simply shrink the desktop design.

On smaller screens:

* Preserve the visual identity
* Simplify complex compositions
* Maintain readable typography
* Keep navigation obvious
* Reduce decorative motion where necessary
* Prioritize content hierarchy

---

The implementation can be decided by Claude based on the design.

Preferred ecosystem:

* Next.js
* TypeScript
* Modern CSS / appropriate styling system
* Semantic HTML
* Accessible components
* Optimized images/assets

# 17. Content Philosophy

The portfolio should communicate **engineering ability through stories and decisions**, not through a giant list of technologies.

Instead of:

> NestJS · PostgreSQL · Redis · Docker · AWS · React · Python · Rust

prefer:

> Built a multi-tenant system where isolated school data, background jobs and high-volume examination workflows had to remain reliable under real usage.

Technology can then support the story.

The portfolio should demonstrate:

**What I build → Why I built it → How I think → What happened.**

**Simple + conventional + obvious**

The portfolio succeeds if a visitor can quickly answer:

1. **Who is Muhyideen?**
2. **What does he build?**
3. **What kind of engineer is he?**
4. **What real software has he built?**
5. **How does he think about engineering?**
6. **How can I contact him?**

And at the same time, the visitor remembers the site because it feels distinctly **Muhyideen**, rather than looking like another developer portfolio.
